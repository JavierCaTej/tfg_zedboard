# T7. Construir Buildroot y generar artefactos Linux base

En esta tarea preparé la build base de Linux con `Buildroot 2023.02.9` para la ZedBoard. Descomprimí la release congelada en `sw/buildroot/`, separé el árbol fuente del directorio de salida mediante `O=` y dejé una defconfig propia del proyecto en `sw/buildroot/configs/tfg_zedboard_defconfig`.

Para evitar repetir comandos manuales, dejé el script `sw/buildroot/scripts/build_buildroot.sh`, que fija la versión de Buildroot, el directorio de salida `sw/buildroot/output/zedboard/` y la defconfig del proyecto. También documenté su uso en `sw/buildroot/README.md`.

Una vez generadas las imágenes, dejé además `sw/buildroot/scripts/sync_buildroot_artifacts.sh` para copiar de forma consistente los ficheros relevantes desde `output/zedboard/images/` hasta `artifacts/buildroot/`, sin depender de copias manuales ni de recordar qué nombre usa cada salida.

La primera build completa se ejecutó correctamente y generó los artefactos principales en `sw/buildroot/output/zedboard/images/`. Como salida trazable de la tarea, copié los ficheros relevantes a `artifacts/buildroot/`: `boot-spl.bin`, `u-boot.img`, `u-boot.elf`, `uImage`, `system.dtb`, `zynq-zed.dtb`, `rootfs.ext4`, `rootfs.tar`, `sdcard.img` y `extlinux.conf`.

El fichero `u-boot` generado por Buildroot se ha conservado como `artifacts/buildroot/u-boot.elf`, ya que es útil como artefacto auxiliar y para diagnóstico del flujo FSBL. Sin embargo, el arranque estable de la SD usa `boot-spl.bin` como primera etapa y `u-boot.img` como segunda etapa.

`T7` queda cerrada como build base reproducible de Buildroot. La descripción específica del periférico `tfg_axi_lite_regs`, la inclusión del bitstream en la SD y la automatización del arranque se consolidan en `T8`.
