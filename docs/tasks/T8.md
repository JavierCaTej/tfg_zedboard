# T8. Adaptar device tree y preparar personalización del rootfs

En esta tarea adapté la base Linux del proyecto para que el sistema conozca el periférico `tfg_axi_lite_regs`. El punto de partida fue el árbol del kernel usado por Buildroot para ZedBoard, tomando `zynq-zed.dts` como DTS de placa y apoyándome en el bus `&amba` ya definido en `zynq-7000.dtsi`.

Primero activé el mecanismo reproducible de parcheo del kernel mediante `BR2_GLOBAL_PATCH_DIR` y añadí los parches necesarios para incluir un `dtsi` propio del proyecto. En ese `dtsi` describí el nodo del periférico AXI4-Lite con `compatible = "tfg,tfg-axi-lite-regs-1.0"`, dirección base `0x40000000`, rango `0x1000` y reloj `FCLK_CLK0` expuesto como `s_axi_aclk`.

Después regeneré la build de Buildroot, confirmé que el `dtb` final incorpora el nodo nuevo y volví a sincronizar los artefactos Linux en `artifacts/buildroot/`. Con esto, el `system.dtb` y `zynq-zed.dtb` actuales ya reflejan la integración hardware que había quedado fijada en Vivado.

También preparé el `rootfs-overlay` del proyecto en `sw/buildroot/board/tfg_zedboard/rootfs-overlay/` y dejé una estructura mínima para configuración, scripts de usuario y pruebas. En esta fase no añadí todavía utilidades funcionales del periférico, pero sí dejé reservado el lugar correcto para incorporarlas sin depender de cambios manuales dentro del rootfs generado.

Con esto, `T8` queda cerrada. El siguiente paso natural es volver a `T6` para empaquetar el arranque final con `fsbl.elf`, el bitstream y `u-boot.elf`, o continuar con las utilidades de validación desde Linux sobre la base ya preparada.
