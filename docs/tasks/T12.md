# T12. Analizar campaigns experimentales y preparar documentacion para la memoria

En esta tarea paso de tener campaigns de medida a tener resultados procesados y documentacion preparada para el TFG. El objetivo es que las pruebas no queden como una coleccion de CSV, sino como evidencia experimental interpretable.

Las campaigns T12 se han ejecutado con `tfg_axi_memtool` usando principalmente el modo `rw-loop`. Este modo escribe en `REG_WDATA`, lee `REG_RDATA` y comprueba que el valor leido coincide con el esperado. Por tanto, cada medida combina latencia y validacion funcional.

## Campaigns ejecutadas

| Campaign | Objetivo |
| --- | --- |
| `A_idle_1h` | Referencia de 1 hora en reposo |
| `B_idle_5h` | Estabilidad de larga duracion |
| `C_cpu_1core_1h` | Medida con un proceso de carga CPU |
| `C_cpu_2core_1h` | Medida con ambos cores ocupados |
| `D_sd_io_1h` | Medida con carga de I/O sobre SD |
| `E_scale_iters_*` | Justificacion del numero de iteraciones |
| `F_trace_detail` | Microtrazas para estudiar picos y dispersion |

## Resultados principales

| Campaign | Runs | Media `avg_ns` | Desv. tipica | Mismatches |
| --- | ---: | ---: | ---: | ---: |
| `A_idle_1h` | 60 | 335.264 ns | 0.013 ns | 0 |
| `B_idle_5h` | 300 | 335.281 ns | 0.014 ns | 0 |
| `C_cpu_1core_1h` | 60 | 335.231 ns | 0.017 ns | 0 |
| `C_cpu_2core_1h` | 60 | 511.386 ns | 11.467 ns | 0 |
| `D_sd_io_1h` | 60 | 340.954 ns | 0.297 ns | 0 |

La referencia en reposo queda alrededor de `335 ns`. La carga con un proceso de CPU no modifica la medida de forma apreciable. La carga con dos procesos aumenta la latencia aproximadamente un `52.5 %`. La carga de I/O sobre SD introduce un incremento moderado de aproximadamente `1.7 %`.

Todas las campaigns tienen `mismatches = 0`, por lo que no se han detectado errores funcionales en las pruebas.
