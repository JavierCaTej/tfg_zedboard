# T11. Automatizar campañas y estructurar la captura de resultados

En esta tarea paso de lanzar medidas manuales a tener una campaña repetible. El objetivo no es añadir complejidad innecesaria, sino poder ejecutar varias repeticiones de `rw-loop` con los mismos parámetros y guardar todos los CSV de forma ordenada.

La automatización se centra en `rw-loop`, que es el modo principal usado para el TFG porque hace escritura en `REG_WDATA`, lectura de `REG_RDATA` y verificación funcional mediante `mismatches`.

He creado el script `measurements/t11/run_rw_campaign.sh`. Este script permite indicar un identificador de campaña, número de repeticiones, iteraciones y warm-up. Antes de lanzar una campaña larga hace una validación mínima leyendo `REG_ID`; si esta comprobación falla, aborta.

Cada ejecución crea una carpeta nueva bajo `/root/t11/raw/` en la ZedBoard, usando fecha y `build_id`. Dentro se guardan:

- `campaign_config.txt`: configuración usada para lanzar la campaña y contexto básico de la imagen usada.
- `campaign_log.txt`: log básico de la ejecución del script.
- `run_001.csv`, `run_002.csv`, etc.: CSV generados por cada repetición.

También dejo el script instalado en el `rootfs-overlay`, en `usr/local/bin/run_rw_campaign.sh`, para poder lanzarlo directamente desde Linux en la ZedBoard.

La copia al overlay se hace con `sw/linux-tests/install_to_rootfs_overlay.sh`. Uso este mismo script porque ya era el punto que actualizaba `tfg_axi_memtool`, así queda todo lo necesario para las medidas en un único paso antes de regenerar la imagen de Buildroot.

## Campañas ejecutadas

Para cerrar la tarea he guardado dos campañas largas dentro de `measurements/t11/raw/`:

- `19700101_001022_t11-rw-1h-60rep`: 60 repeticiones de `rw-loop`, con una duración total aproximada de 1 hora.
- `19700101_012744_t11-rw-2h-120rep`: 120 repeticiones de `rw-loop`, con una duración total aproximada de 2 horas.

En ambas campañas se usaron los mismos parámetros de medida:

- `iters = 180000000`
- `warmup = 1000000`
- operación medida: `rw-loop`
- dirección base: `0x40000000`

El resumen agregado queda en `measurements/t11/summary/t11_campaign_summary.csv`.

| Campaña | Repeticiones | Media `avg_ns` | Desv. típica | Mínimo | Máximo | Mismatches |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `t11-rw-1h-60rep` | 60 | 335.179650 ns | 0.024080 ns | 335.144000 ns | 335.259000 ns | 0 |
| `t11-rw-2h-120rep` | 120 | 335.166267 ns | 0.042394 ns | 335.058000 ns | 335.287000 ns | 0 |

Las fechas aparecen como `19700101` porque la ZedBoard no tenía hora real configurada al arrancar. Para esta tarea no afecta al resultado porque el objetivo era validar la estructura de campaña y la estabilidad de las medidas, no usar la marca temporal como referencia absoluta.


Ejemplo de uso:

```bash
run_rw_campaign.sh \
  --id t11-rw-100M-warmup-1M-5rep \
  --reps 5 \
  --iters 100000000 \
  --warmup 1000000
```

Con esto, `T11` queda cerrada a nivel de automatización, captura estructurada y primeras campañas largas de referencia.
