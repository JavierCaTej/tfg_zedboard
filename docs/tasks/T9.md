# T9. Asegurar una SD estable

En esta tarea dejé cerrada una imagen SD estable para la ZedBoard a partir de la build de Buildroot. El objetivo fue pasar de una imagen que arrancaba Linux a una imagen que además cargase automáticamente la PL con el bitstream del proyecto antes de acceder al periférico AXI-Lite.

La decisión final fue mantener el flujo de arranque `U-Boot SPL`, porque era el flujo que ya había demostrado arrancar correctamente en placa. El `BOOT.bin` generado con `FSBL` y `bootgen` queda conservado como artefacto de diagnóstico, pero no es el primer cargador usado por la SD estable.

Para generar la partición de arranque dejé un `post-image.sh` y un `genimage.cfg` propios en `sw/buildroot/board/tfg_zedboard/`. Con esto, la partición `boot` de la `sdcard.img` incluye `boot.bin`, `u-boot.img`, `uImage`, `system.dtb`, `extlinux/extlinux.conf` y el bitstream `tfg_zedboard_bd_wrapper.bit`.

Después automaticé la carga del bitstream desde U-Boot mediante `sw/buildroot/board/tfg_zedboard/uboot/bootcmd.config`. Este fragmento fija `CONFIG_BOOTDELAY=-2` para evitar que la consola UART detenga el arranque y define un `CONFIG_BOOTCOMMAND` que carga el `.bit` desde la SD, programa la PL con `fpga loadb` y continúa el arranque Linux con `run distro_bootcmd`.

La imagen estable queda documentada en `docs/boot/sd-estable-buildroot-uboot.md`. La validación final en placa confirmó que Linux arranca sin intervención manual y que el periférico responde correctamente:

```text
devmem 0x40000000 -> 0x54464700
```

Con esto, `T9` queda cerrada. La salida principal de la tarea es `artifacts/buildroot/sdcard.img`, entendida ya como SD estable con carga automática del bitstream y acceso funcional al periférico AXI-Lite.
